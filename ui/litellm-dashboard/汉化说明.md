# LiteLLM UI 汉化分支（v1.109.1）

> **分支基线**：fork 的 `main`。上游较新版本已不带 `ui/` 目录，所以本分支把
> `v1.109.1` 的 `ui/litellm-dashboard` 作为独立目录加回来；其余代码保持 `main`，
> 不修改后端/工作流。UI 目录本身可直接 `npm ci && npm run build`。

这个目录取自 LiteLLM `v1.109.1` 的 `ui/litellm-dashboard`，用于食汇网关的
中文界面。**不是官方 i18n**：官方 `en.json` 只覆盖 workflows / policies /
guardrails，所以这里用源码级替换。

## 当前覆盖

- 登录页、左侧导航、首页概览、虚拟密钥、模型与端点、日志、用量、团队、用户、
  组织、预算、防护规则、策略、路由设置、成本、MCP、技能、向量库、提示词、
  项目、缓存、日志告警、管理设置、API 文档、UI 主题等页面；
- 表单标签、表格列头、按钮、空态、分页、搜索框、提示/错误文案、账号菜单、
  深色模式、通知、侧栏折叠等界面文案；
- `zh-dict.json` 目前约 **714 条**；`translate.mjs` 替换 JSX 文本、显示属性、
  对象里的显示值（label/title/description/header/placeholder 等），不碰
  href、路由、状态枚举和逻辑值；
- 构建：`npm ci && npm run build`（Node 24+）。

## 词典 / 继续汉化

- `zh-dict.json`：英文 → 中文；只放**显示文案**，不要放 status/role 等逻辑值；
- `translate.mjs`：按词表扫描 `src/`（跳过测试）；可重复运行，已翻译的中文不会重复处理；
- `extract-strings.mjs`：只读扫描源码，输出 `zh-candidates.json/.txt`，用来找
  还没翻的显示文案；新增词条后重跑 `node translate.mjs`，再 build；
- 动态拼接句/后端 metadata 由部署侧的运行时补丁 `litellm-zh.js` 兜底
  （由 `deploy/ai-gateway/zh/gen-zh-patch.py` 从同一个 `zh-dict.json` 生成）。

## 生产部署（食汇网关）

- 构建产物 `out/` 上传到 `/opt/shihui-ai-gateway/ui-zh-out`；
- 用 `deploy/ai-gateway/docker-compose.ui-zh.yml` 覆盖层挂到 LiteLLM 镜像的
  `.../litellm/proxy/_experimental/out:ro`，容器 recreate 不丢；
- Nginx 的 `litellm-zh.js` 运行时补丁仍保留作兜底。

## 已知边界

- 品牌/供应商/模型名称（LiteLLM、OpenAI、Anthropic、Gemini、DeepSeek 等）、
  日期/数字、API 路径、代码片段、快捷键（Ctrl K / ⌘J）、新闻/博客内容保持英文；
- 少数后端 metadata 的 Title Case 文案由运行时补丁翻译（CSS 大写显示）；
- 本分支是 v1.109.1 的 UI 源码，升级 LiteLLM 时需重新 rebase 并补新文案。
